## 0. 一句话结论（先看这里）

**四地点必须换四套「建造动词」，而且四个动词必须落在四个不同的空间维度上。**

| 地点 | 动词 | 空间维度 | 一句话 |
|---|---|---|---|
| 雾港·泉州湾 | **连** | 水平 · **线** | 把屿、桥、厝串成一条活的水道 |
| 圣托里尼 | **凿 / 悬挑** | 垂直 · **向外** | 从崖壁上要出一片白蓝城 |
| Cape Cod | **照** | 水平 · **面** | 用灯塔光锥把海岸铺满 |
| 塞舌尔 | **叠** | 垂直 · **向上** | 把花岗岩圆石堆成一座不会倒的岛 |

**四个维度互不重叠：线 / 面 / 向外 / 向上。** 这是「不是换皮」的结构性证据，比任何美术对比都硬。

第二个必须先说破的结论：

> **成本分级里 S 级（只换美术）= 0 款。**
> 四地点全部要动系统逻辑。这既是好事（证明不是 asset flip），也是约束——
> **总工作量约 81～108 人日（点估 94；含共享底座 18，区间 17～20）**，Benja 必须先做 `core` 共享底座，否则维护四套分支会把他压垮。

## 1. 产品形态变了，设计约束也跟着变

v1.0 方案是「六款独立游戏」，现已被拍板改为「**单一产品内置多个地点**」。这不是文案改写，它改变了三件事：

### 1.1 asset flip 的指控自动消解，但代价是另一条指控

「同一产品加新地图/新城市包」是行业惯例（Cities: Skylines、Planet Zoo 都是这么卖的），玩家不会骂。
但由此产生**新的指控风险：「拆内容卖」**——如果玩家觉得某个地点本来就该在首发里，就会骂。

**设计侧的唯一解药：每个地点的动词必须真的换了。** 只要动词换了，它就是「新玩法内容」而不是「被拆掉的地图」。
所以 **1.2 的差异化要求是硬底线，不能因为改成同一产品而降级。**

### 1.2 三条设计支柱（四地点通用，不可动摇）

| 支柱 | 含义 | 检验方法 |
|---|---|---|
| **P1 松弛无压** | 无失败态、无倒计时、无资源枯竭、无威胁 | 关掉游戏时玩家不会焦虑；任何机制不能"惩罚"玩家 |
| **P2 从无到有的成就感** | 看得见的积累 + 明确的"落成时刻" | 每个地点都要有一个**可截图的高光瞬间** |
| **P3 微缩景观审美** | 体素式拼搭、可俯瞰的盆景感 | 玩家会主动按 P 键拍照 |

**红线（四地点全部适用）**：不引入战斗、生存压力、数值经济、失败结局。任何一条被破坏，这个产品的口碑基础就没了。

### 1.3 新增的共享成本（v1.0 没有，现在必须做）

产品形态从「一个游戏」变成「一个游戏 + 地点切换」，底层多了四件事：

| # | 新增件 | 说明 |
|---|---|---|
| 1 | **地点切换器** | 主菜单 → 地点选择 → 进入。**UI 新增**，是产品的门面 |
| 2 | **`LocationProfile`（.tres）** | 每地点一份参数资源（水体/光线/雾/建材表/地形参数），运行时切换 = 换资源（见 `water-lighting-params.md`） |
| 3 | **地点资产按需加载（几何数据化 + 运行时 ArrayMesh）** | ⭐ **架构前提，不是优化**（见 `tech-feasibility.md` §4.2 定案）。<br>✅ **实现路线已换**：`.pck` + `load_resource_pack()` **可行但不推荐**（引擎版本锁 + 挂载后无法卸载），改走**几何数据 dump + 运行时 `add_surface_from_arrays`**（可选 IndexedDB 缓存）。<br>⚠ **按需加载的理由也要换**：**不是为了包体**——已导出 `index.pck` 仅数百 KB，43.6MB 首屏是引擎 wasm 本体、与地点资产几乎无关；真正的理由是**内存 / DLC 交付通道 / 加地点不必重导主包**。<br>🔄 `.pck` 只在未来某地点引入贴图资源时才重走决策（判定口径见 §4.9.2 ⑤） |
| 4 | **存档按地点隔离** | JSON 加 `location_id` + `schema_version`；跨地点导入给明确提示，不静默失败 |

**设计侧立场**：地点在菜单里**全部可见、全部可进**。不要做灰掉的锁图标、不要做"购买"按钮——那种设计会瞬间摧毁 P1 的松弛感。商业化放在商店页，不放在游戏里。

### 1.4 手感必须四地点完全一致（这是系列的另一半）

机制要不同，**肌肉记忆必须相同**。以下七项四地点一行代码都不要改：

1. 相机操作（环绕 / 缩放 / 平移的键鼠映射与阻尼系数）
2. 建造操作（左键放置、右键/删除、R 旋转、撤销快捷键）
3. UI 布局（建材栏位置、顶栏、提示条）
4. 昼夜切换（N 键）与拍照模式（P 键）
5. 存档 JSON 的 schema 结构（只增字段，不改结构）
6. 撤销深度 160 步、建材上限 12000（可上调，不可下调手感预期）
7. **进入/退出地点的路径与确认方式**

**新增规则的教学原则**：不开局弹教程墙。**玩家第一次选中相关建材时，建材栏下方浮现一句话**，学完即走。
例：选中"楔石"时提示「楔石塞进石缝，能让上面的石头站得更稳。」

### 1.5 一个地点只允许一个 `location_mechanic`

```
core/（共用，只维护一份）
  网格与坐标系统、放置/拆除/撤销栈
  相机控制器、输入映射、UI 框架
  昼夜循环、水面基础、拍照模式、JSON 存档读写
  建材基类（含多格构件基类 ← 灯塔机制已验证）
  地点切换器、LocationProfile 加载、几何数据化资产挂载（运行时 ArrayMesh）
  ⚠ 不是 .pck 分包挂载——.pck 路线已不采用（见 §1.3 与 §4.9.2 ⑤）

locations/（每地点一份）
  terrain_generator.gd   ← 地形生成器
  location_mechanic.gd   ← 该地点唯一的新机制模块
  materials.tres         ← 建材表
```

**硬性约束**：每个地点**只允许新增一个** `location_mechanic`。需要两个以上系统，说明设计超载，必须砍。

### 2.1 雾港 · 泉州湾（Zayton / 刺桐港，中国福建）

#### 核心机制（一句话）
> **把散落的屿、桥、厝连成一条活的水道——连通那一刻，灯火从水边一路亮进村里。**

#### 为什么泉州（不只是"换皮"，而是给现有资产一个真实身份）

现有 13 建材的色值**天然就是闽南建筑**，几乎零改色即获真实身份：

| 现有建材 | 色值 | 泉州身份 |
|---|---|---|
| 陶砖 | `c8856b` | **红砖古厝**墙面（闽南红砖） |
| 坡屋顶 | `c67360` | **红瓦**屋面（双坡曲） |
| 石基 | `b9bcad` | **白石基座 / 出砖入石**（蚵壳厝镶边） |
| 木栈道 | `bb946c` | **码头栈道** |
| 桥拱 | `d4cfb8` | **洛阳桥 · 安平桥**（宋石梁桥） |
| 海湾小屋 | `d1826b` | 改**闽南立面** |
| 灯塔 | `d08067` | 航标（建议改**石构航标塔**，见下） |

这是本项目最大的一次"白捡"：**美术成本几乎为零，文化身份却是顶级。**

#### 真实地理 / 文化锚点
- **泉州：宋元中国的世界海洋商贸中心**（2021 UNESCO 世界遗产），宋元东方第一大港，海上丝路起点
- 海外认知 **Zayton**（马可·波罗、伊本·白图泰记载刺桐港）
- **洛阳桥**（万安桥，1053–1059，蔡襄）：**筏形基础 + 种蛎固基**，世界首创

   > **作废范围**：DEPTH 四态数值 · 「泉州专属三条判据」· **「塞舌尔落差 1.42 / 圣托里尼 12.4% 不适用」的整块说明** · `density ≤ 0.25`（硬顶 0.2713）· `density ≤ 0.018` · `x_end` 安全调参表 · 「近处对 `density` 免疫」· 单位陷阱（`begin/end` 不是格）· V1 / V3 / V4。
   > 📌 **说明块一并删除的理由**：判据作废了，**解释"为什么它不适用"就没有对象了**——留着只会让人以为判据还在。
   >
   > **继承下来的三条**：① **相机事实**（正交投影 / 轨道半径 48.0 / pitch / zoom，与雾模式无关）；② **V2：`fog_disabled` 是显式 token，`unshaded` 不绕雾**（材质事实，与雾模式无关）；③ **「雾永远不能挡住建造区」这条设计底线**（改由观感判据承接）。

#### 新增系统规则

**R1 · 连通链判定（核心，全程不显示任何数字）**

链条（四环）：

```
石构航标塔（湾口/屿上）
   │  水面可达（直线水道，无遮挡）
   ▼
码头栈道（水陆接口）
   │  相邻
   ▼
蚵壳厝（岸上民居）
   │  相邻
   ▼
红砖古厝聚落（内陆）
```

- 判定方式：**陆地相邻 + 水面直线可达**的 BFS（比嵊泗的水道判定更简单，逻辑轻量）。
- **每接通一环，开一层"活的"表现**（不显示数字、不设产率、不设进度条）：

| 环 | 接通后发生什么 |
|---|---|
| 航标塔 ↔ 栈道 | **渔船归港**：2–3 艘低模渔船沿固定航路从湾口驶入，停靠栈道，随水面轻晃 |
| 栈道 ↔ 蚵壳厝 | **晾晒与海蛎**：厝前挂渔网，竹匾摊开海蛎与鱼干。白天晾晒、夜晚收起（随昼夜变化） |
| 蚵壳厝 ↔ 古厝 | **灯火次第亮起**：窗口与檐角灯笼**按从水边到内陆的顺序**依次点亮（约 0.15s/栋），夜间触发 |
| 全链通 | **刺桐花开 + 万家灯火**：湾口刺桐满树红花；整片聚落灯火通明，水面出现暖色倒影 |

> **「灯火次第亮起」是泉州的落成高光，也是全产品最强的一张截图。**
> 它是"安静的仪式感"，不是"恭喜达成 +100"。
>
> 🟢 **性能隐忧已解除（2026-09-24，程基岩核定）**：曾被担心"20 栋次第点亮 = 20 次全岛 ArrayMesh 重建"。
> **实际不会**——改用 MultiMesh 后，点亮一盏灯只是改一个实例的 transform 与颜色 + 一个计数，**不存在重建**。
> → **「从水边到内陆、0.15s/栋」的时序与串联动线完整保留，不需要为性能做任何让步。**
> ⚠ **性能红线（已被字节码反汇编证实，不是纸上推演）**：灯火**绝不能**是真实 `OmniLight3D`。
> `godot-web-perf.md` §2 落笔于 9 月 23 日，**当时我们一行源码都没看过**，那句话是仅凭 Godot Web 端渲染常识做出的**前瞻判断**；
> 今天 `build_world.gd::_add_prop()`（L224–231）的反汇编证实这个推断完全正确，还额外暴露了一层当初没预料到的恶化——地形是全岛合并的单 ArrayMesh，于是 per-mesh 的 8 盏上限变成**全岛共享 8 盏**（见 §5 R-4 与 `tech-feasibility.md` §2）。
> ✅ **现方案：共享光斑贴片**（单 quad + 不受光材质 + MultiMesh，混合模式已由 `blend_add` 改为 **`blend_mix`**——密排时加法会 clip 成纯白）。零重建、零灯光预算、可贴任意面（含墙面）。
> **「灯火次第亮起」（从水边到内陆 0.15s/栋）的设计不用改。**

**R2 · 种蛎固基（文化彩蛋，非系统）**
- 洛阳桥的真实工艺：桥墩抛石上**养殖牡蛎**以固基。
- 表现：桥拱 / 石基放置于水下时，表面**逐渐长出蚝壳纹理**（shader 遮罩阈值动画，非每帧生成实例）。
- 与蚵壳厝的蚝壳墙形成呼应——**同一材料，一个固桥，一个砌墙**。这是泉州独一份的叙事细节。

**R3 · 引导（防看不懂，非压力）**
- 未接通的下一环，地面显示**极淡的微光箭头**，**默认关闭**、可一键关。
- 第一次接通某环时，建材栏下方浮现一句中文：「浮筏与码头连通了，渔船开始往返。」（泉州版：「航标与栈道连上了，渔船开始归港。」）

#### 声音签名
- 环境：湾内平缓潮声 + 鹭鸟 + 极远的渔船马达 + 风穿榕叶
- 音乐：**南音气质**的极简氛围（洞箫 / 横抱琵琶音色）。南音是世界非遗，气质极静，与 P1 完美契合。
  ⚠ 只用南音的**音阶与乐器音色做氛围化编排**，不标榜"正宗南音"，避免文化争议。
- 晨态：橹声、鸡鸣（**规避宗教音效**——泉州是"世界宗教博物馆"，见 R-9）

#### 新增系统规则

**R1 · 悬挑（Cantilever，v1.0 独占机制）**
- 从"锚固在实心崖体"的格子算起，向外最多悬挑 **3 格**（1 格≈1m）。
- 悬挑 2 格以上时，砖块呈现**微下沉 + 支撑木痕**（纯表现，不失败）。
- 想悬挑更远？必须加**扶壁柱**（复用桥拱，翻转 90°）。

**R2 · 凿崖（Yposkafa，负建造）—— 留到 1.1（首发债务，需在 1.1 偿付）**
- 只能凿凝灰岩崖体格，凿后形成 1 格空腔，可内装地板/灯。
- **凿除不计入建材上限**（是减法），UI 明示，玩家会觉得赚到。
- ⭐ **为什么必须延后**：① 技术不确定性最高（依赖地形数据结构，若地形与建材不同 GridMap，需重建 chunk）；② 一个地点只允许一个新系统（悬挑已占名额）。

> ### ⚠️ 「留到 1.1」的准确定性（口径更正，2026-09-24）
> **1.1 的性质：债务偿付窗口优先。** 首发遗留的 19–33 人日必须在 1.1 偿付；**偿付完成后若有余力，才是新增内容与由此产生的曝光。**
> ⚠️ **禁止的推论**：**不得把"1.1 是免费曝光"当作在 1.0 砍内容的理由**——那等于把欠账包装成赠品，等于论证了当初就不该砍。
> 📌 **对外沟通上，1.1 仍可正常表述为一次内容更新**；"债务"是**内部计划定性**，不是外部话术。
>
> 拆开说：作为**市场事实**，"1.1 带来曝光"成立——玩家不知道我们内部把它叫债务，1.1 上线真有内容，对外就是一次更新节点，确实有曝光，这一层不能抹掉；
> 但作为**计划论证**，它不成立——如果它的作用是论证"可以先把内容砍到 1.1 再送"，那它就是在给债务陷阱做辩护。
> ⚠ **1.1 的内容清单与人日本轮一律冻结**，本次只改定性、不动数字。完整口径见 §4.7.2。

### 2.3 Cape Cod（美国马萨诸塞，大西洋沙质半岛）

#### 核心机制（一句话）
> **在夜与雾里织一张光网——用灯塔的光锥覆盖整条海岸，让夜晚没有暗角。**

#### 与泉州的本质区别（**必须处理，这是本项目最大的撞车风险**）

| | 泉州「连」 | Cape Cod「照」 |
|---|---|---|
| 判定类型 | **线**的连通（BFS 可达） | **面**的覆盖（距离 + 遮挡） |
| 光的角色 | **结果**：连成了才亮，被动奖励 | **手段**：玩家主动布置光源 |
| 光的形态 | 点状、暖橙、**人间灯火** | 锥状、冷白、**导航光** |
| 玩家心智 | 建筑师（造实体） | 灯光师（造关系） |

四地点里只有这两款玩"光"。**区隔成立，但排期上必须隔开**（见第 4 章：Cape Cod 排第 4）。

#### 真实地理 / 文化锚点
- **Nauset Light**（红白条纹，最上镜）、**Highland Light**（最老最高，崖顶）、**Chatham Light**
- **Three Sisters of Nauset**：三座曾并排的小灯塔，Cape Cod 独有奇景
- **Weathered gray cedar shingles**：海风盐雾风化成的银灰色木瓦，Cape Cod 建筑最标志性的质感
- **Cranberry Bog（蔓越莓沼泽）**：秋季"水收"时整片沼泽变血红色——**全产品最强的季节视觉爆点**
- Salt marsh（盐沼）、沙丘与 beach grass、龙虾笼与浮标

- ~~**只有玩家视口附近 2–3 座灯塔用真实 SpotLight3D**，其余全部用**半透明光锥 mesh + additive blending（假体积光）**。~~ 🗑️ **已作废 · 勿用 · 勿删（v2.5 · D-CC-1 拍板 2026-09-25）**——旧表述与 §4.9.2 ⑦-A 放行口径（四地光表现**统一走同一套贴片体系**，不再并存「真实光源 / 假光」两条路线）和 ⑥ 真实点光源禁令冲突，留此仅作沿革。

### 2.4 塞舌尔（Seychelles，印度洋花岗岩岛）

#### 核心机制（一句话）
> **在白沙滩的花岗岩巨石上，堆一座不会倒的岛——垫稳一块，石缝就会长出花。**

#### 为什么塞舌尔是第四种空间挑战（这是它入选的根本理由）

| 形态 | 代表 | 动作的本质 |
|---|---|---|
| **砌**（人工砌筑） | 马耳他（候选池） | 构件**咬合**承重——精确、有梁有柱 |
| **悬挑**（向外延伸） | 圣托里尼 | 向**崖外**要空间——受锚固距离约束 |
| **叠**（向上堆叠） | **塞舌尔** | **重心平衡**——受接触面与层高约束 |

**塞舌尔是"向上的平衡"，是第三种、也是最后一种空间挑战维度。** 它与圣托里尼同属垂直，但方向完全相反：一个向外悬空，一个向上叠稳。

**地质成因也与圣托里尼天然对立**：海洋岛通常是火山岛或珊瑚岛，**花岗岩岛是全球罕见的大陆碎片型**（塞舌尔是冈瓦纳大陆裂解的残留，约 7.5 亿年前的花岗岩）。这两个岛在地貌、色彩、成因上都是反义词——**宣传上"火山岛 vs 大陆碎片"是一组极好的对照。**

#### 真实地理 / 文化锚点
- **Anse Source d'Argent**（拉迪格岛）：世界上被拍得最多的海滩之一，巨型圆花岗岩 + 白沙 + 绿松石水
- **海椰子（Coco de Mer）**：塞舌尔国宝，世界最大的种子，仅普拉兰岛五月谷原生
- **Takamaka**（红厚壳）：海滨标志性大树，向海倾斜生长
- **象龟（Aldabra Giant Tortoise）**：塞舌尔的国家象征
- **Anse Lazio**（普拉兰岛）、**Anse Intendance**（马埃岛）
- 克里奥尔文化：木质 + 茅草顶的 Creole 小屋

| 项 | 建议值 | 备注 |
|---|---|---|
| 岛形 | 中央花岗岩低丘 + 环岛白沙滩 + 浅礁泻湖 | 与泉州的"湾+屿"、圣托里尼的新月崖都不同。✅ **岛形基准注记（SY-D-10 已裁定，2026-09-25 Benja）**：概念图为环礁式中央潟湖构图，与本档岛形描述存在偏差——**以本档文字为准**，概念图仅作俯视双层水机位参考（回源 `seychelles-spec.md` §8） |

#### 新增系统规则

**R1 · 稳度（Steadiness）—— 一个不显示的隐藏量，只通过视觉表现**

- 每块石头有 `contact_ratio` = **底面落在下方实心格（地形/石/楔石）的格数 ÷ 底面格数**
- `n` = 该石下方到最近实心地面的堆叠层数
- 稳度阈值 `T(n) = 0.30 + 0.05 × n`，上限 **0.70**
  （n=1 → 0.35；n=3 → 0.45；n=5 → 0.55；n≥8 → 0.70）

| 判定 | 表现 |
|---|---|
| `contact_ratio ≥ T(n)` → **稳** | 静止，可继续往上叠 |
| `contact_ratio < T(n)` → **摇** | **缓慢摇晃动画**（±1.5°，周期 2.4s）+ 石缝**细碎落屑粒子** + 放置音偏闷。**上方不可再叠**（唯一硬限制） |

**这就是"越往上越需要配重/平衡"的具体化——阈值随层数收紧。**

**R2 · 三种手段（玩家的技巧成长曲线）**
1. **垫**：楔石塞进石缝 → 提升 `contact_ratio`（每块 +1 格接触）
2. **转**：巨石 4 向旋转（R 键），**不同朝向重心不同** → 选朝向是一门手艺
3. **收分**：大石在下、楔石作顶石 → 自然金字塔形。**越高越难，玩家自发学会收分**

**R3 · 天然石拱（叠机制的自然延伸，不是新系统）**
- 两块等高巨石间距恰好 2–3 格且都"稳"时，顶上可放一块**横梁石**（复用桥拱改色）→ 形成天然石拱。
- 对应 Anse Source d'Argent 的真实天然石拱。
- **它是"叠"的副产品，复用同一套接触面判定，不占 `location_mechanic` 名额。**
- ⚠ 若未来做马耳他（候选池），必须明确区隔：**叠 = 重心平衡；砌 = 构件承重咬合。**

**R4 · 落成表现（生态反馈，不是数值反馈）**

当一座石堆达到 **N 层且全稳**（所有石头 `contact_ratio ≥ T(n)`）：

- 石缝间**长出岩生海芋 / 蕨类**（绿色沿缝蔓延，shader 遮罩动画）
- 石堆旁的**白沙滩上出现一只象龟**，缓慢爬行
- 石堆投下的**浓荫里出现一小片水洼倒影**（赤道强光的硬阴影在这里变成构图主角）

> **⚠ 红线：不显示层数、不排名、不设最高纪录。**
> 反馈是"它长出了植物 / 有龟来住"——生态反馈，不是数值反馈。
> 一旦做成"谁堆得高"，塞舌尔就从松弛沙盒变成挑战游戏，P1 直接崩。

#### 声音签名
- 环境：环礁外的长浪（被礁石过滤后变闷）+ 棕榈叶摩擦 + 热带鸟鸣
- 巨石：放置时**低沉的石头闷响 + 尘土感**；"摇"的石头音更闷、带细碎落屑声
- 音乐：极简打击乐 / 木质音色 + 留白（呼应克里奥尔文化，慎用"世界音乐"套路）

#### 独特卖点
> **「在白沙滩的花岗岩巨石上，堆一座不会倒的岛。」**
> 副标题：越往上越难。垫稳一块，石缝就会长出花。

#### 前 30 分钟体验曲线 & 深度评估

| 时段 | 玩家在做什么 | 学到的技巧 |
|---|---|---|
| 0–5 min | 在白沙滩的散落巨石上试着叠第二块 | 有的角度放上去会"晃" |
| 5–15 min | 学会用楔石垫稳，堆到 4–5 层 | **垫**（楔石） |
| 15–25 min | 发现越高越难，改用大石在下小石在上 | **转**（朝向）+ **收分** |
| 25–40 min | 石缝长出海芋，象龟来了；追求石群构图 | 稳 = 生态奖励 |
| 40 min+ | 追求整岛的"石头语言"：石群、石拱、巨石与海椰子的组合 | 审美创作 |

**深度：★★★★☆**
起步零门槛（地形自带巨石），技巧曲线清晰（叠 → 垫 → 转 → 收分 → 构图）。
**风险**：**"高度诱惑"**——玩家会本能地想堆最高。对策就是 R4 的红线（不显示层数、不排名）。

> ### ⚠ 雾档位与四态的关系（v2.3，防止读成自相矛盾）
> **四态是"光照四态"，雾是"两档常量"**——二者是**两个正交的维度**，不是同一件事：
> - **四态**（晨 / 昼 / 日落 / 夜）决定的是**太阳色、水色、天色、光照能量、阴影柔度**；
> - **雾档**（昼档 / 夜档）决定的是**远处被抹掉多少**；**晨与日落沿用昼档**。
>
> 📌 **Cape Cod 为什么有三档**：它的「雾」**不是昼夜循环里的一个态，而是正交的天气开关**（§4.8.1 ① 已定：**前者是"时刻"、后者是"状况"，语义不同，不能挤进同一个状态机**）。
> → 所以 Cape Cod 的**雾档**是"天气开关打开时额外用的一套雾常量"，**与"雾只有昼/夜两档"这条不冲突**——那条说的是**昼夜循环**，这条说的是**天气开关**。
> ⚠ **请勿把两者合并**：合并会让四地的状态集合不等价，硬等价即告破（见 §4.8.1 ①）。

## 4. 成本分级与开发优先级

### 4.1 分级定义

| 级别 | 定义 | 本文判定 |
|---|---|---|
| **S 级** | 几乎只换美术 + 少量建材，**不新增任何系统逻辑** | **0 款** |
| **A 级** | 新增**一个**中等系统（约 10–20 人日） | 2 款 |
| **B 级** | 新增**一个核心系统 + 地形生成器改造**（约 20–35 人日） | 2 款 |

> **「S 级 = 0 款」是最重要的结论。**
> 它同时回答两件事：① 这个产品**不是** asset flip；② 但它也**不是**四款重做。
> 注意：**泉州的美术成本近乎为零（13 建材色值直接就是闽南建筑），但它的系统成本（连通链）是真的**——所以它是 A，不是 S。省钱省在美术，不在系统。

### 4.5 开发优先级排序与理由

| 排产 | 地点 | 一句话理由 |
|---|---|---|
| **0** | **core 底座** | 不做这个，第四款会死于维护成本。**与泉州并行推进** |
| **1** | **泉州·雾港** | 本体已在，改造成本最低；且它是验证 `LocationProfile` 管线的第一款——**必须用最便宜的一款去验证管线，不能用最贵的** |
| **2** | **圣托里尼**（v1.0 悬挑） | 视觉差异最大，是首发主视觉，也是唯一能在**截图层级**证明"不是换皮"的一款。**凿崖留 1.1** |
| **3** | **塞舌尔** | 紧接圣托里尼做，可**共用垂直建造的技术投入**（多格构件、垂直剔除、锚固/接触判定有共通模块）。且「向上」与「向外」形成极好的宣传对照："一个向外，一个向上" |
| **4** | **Cape Cod** | 性能不确定性最高，留到最后有前三个地点的时间缓冲；且**与泉州的光母题必须错开**（它是唯一与泉州玩"光"的一款） |

#### 为什么是 泉州 → 圣托里尼 → 塞舌尔 → Cape Cod（四条理由）

1. **泉州第一**：它是"在本体上改造"，core 底座与它强耦合。**用最便宜的一款验证管线**——如果 `LocationProfile` 切换或**资产加载管线**（几何数据化 + 运行时 ArrayMesh）有问题，在泉州上发现的修复成本最低。
2. **圣托里尼第二**：第一印象只值一次，必须买最贵的。它是唯一能在缩略图尺寸下就与泉州区分开的一款（白蓝悬崖 vs 青灰港湾）。**v1.0 只做悬挑，凿崖留 1.1**——切分风险（技术不确定性 + 一个地点只允许一个新系统）。
   ⚠ **「留 1.1」不是"攒着以后送"**：**1.1 是债务偿付窗口**——首发遗留的人日必须在 1.1 偿付，**偿付完成后若有余力才是新增内容与曝光**。
   📌 **禁止的推论**：不得把"1.1 是免费曝光"当作在 1.0 砍内容的理由（那等于把欠账包装成赠品）。对外 1.1 仍可表述为一次内容更新；"债务"是内部定性，不是外部话术。完整口径见 **§2.2 R-2 / §4.7.2**。
3. **塞舌尔第三而非第二**：
   - 圣托里尼必须第二（主视觉 + 反换皮证据）；
   - 塞舌尔紧接着做，与圣托里尼**共用垂直建造的底层投入**（多格构件吸附、垂直剔除、邻接支撑判定），排一起有技术协同，能省 3–5 人日。
4. **Cape Cod 第四**：
   - ① **性能不确定性最高**（WebGL2 动态光源数量），放到最后有缓冲；
   - ② **与泉州的"光"母题撞车**，排最后可最大化间隔；
   - ③ 它是**传播型内容**（夜景光锥短视频完播率高），适合作**首发后的第一波更新**曝光，而不是首发当天被另外三个地点淹没。

### 4.7 首发最小完成度门槛（M1–M6）与可延期项清单

> 依据运营定案的约束 1「统一最小完成度，任一地未达线则整体延期」。
> 以下 **M1–M6 是四地点统一适用的地板线**（其中 **M6 为产品级，四地点共用、只需做一次**），不因地点级别（A/B）而放宽。

#### 4.7.1 六项首发门槛（每个地点都要过；M6 为产品级，四地共用）

| # | 门槛 | 验收判据 |
|---|---|---|
| **M1** | **地形与视听成型** | 地形生成器完成；地表/水体/光线参数已套上该地点的 `LocationProfile`；**缩略图尺寸下能一眼认出是这个地方** |
| **M2** | **动词成立** | 该地点独占的 `location_mechanic` 已上线并通过**手感验收**（不是"能跑"，是"好玩"） |
| **M3** | **建材齐活** | ≥ 4 种新建材 + 复用件改造完成；**承担动词的那件主力建材必须在内**（泉州=桥拱/航标塔、圣托里尼=白墙屋、塞舌尔=巨石+楔石、Cape Cod=高地灯塔） |
| **M4** | **落成高光可达** | 该地点的高光时刻可稳定复现，且**在日落或夜晚状态下可截图** |
| **M5** | **引导完整** | 6 条新手目标 + 新规则的「选中建材浮现一句话提示」 |
| **M6** | **⭐ 分享闭环（产品级，非地点级）** | 拍照模式（P 键）拍完**必须有分享出口**（保存到相册 / 复制到剪贴板 / 一键导出分享图）。**现状：P 键存在但拍完无出口，闭环是断的** |

> **为什么是这六条**：M1 对应 P3，M2/M3 对应动词差异化，M4 对应 P2 成就感，M5 防流失，M6 对应可分享性。
> 缺 M2/M3 = 该地点退化成换皮，**这是最不能被接受的一种未达线**；
> 缺 M4 = 玩家没有可分享的画面；
> **缺 M6 = 有画面也传不出去。**
>
> ⚠ **M6 是必补项，不是优化项。**（经 team-lead 确认，2026-09-23）
> 理由：本产品的商业循环是**内容消耗型**——玩家买的是「内容量 × 可分享性」。
> 可分享性这一环断了，M1–M6 全部白做：**玩家拍了照但传不出去，K 指标里的"可分享性"就转不成真实曝光。**
> 它不隶属于任何单一地点，是**产品级门槛**，四地点共用、只需做一次，但**不做则整体不达线**。

### 4.8 设计侧放行的理由与触发条件

> ### 📌 适用范围声明
> **以下只定义触发条件和放行口径，不提供任何具体数值。数值由具体实现时测定，测定方法见对应技术文档。**
>
> 本节存在的理由：**有"条件"没"量"，对一线是"让我自己判断"；有"量"没"条件"，对专家是"让我照抄一个可能已失效的数字"。**
> 所以本节只回答两个问题：**什么情况下该做什么决定**、**做到什么样子算放行**。具体阈值一律回源至 `tech-feasibility.md` / `reskin-matrix-assessment.md`。

#### 4.8.1 四条已批项的设计侧理由

| # | 已批项 | 设计侧理由（为什么不这么做会出问题） |
|---|---|---|
| **①** | **硬等价划线 + 强制 A/B**：所有四地 day/night 走同一条 `set_night()` 分支 | 四地点一旦各写一份昼夜分支，就会长出四套参数语义（"日落"在泉州是暖金、在 Ria 是蓝灰，若不走同一条分支，两地会各自演化出不同的插值方式），后续任何一次光线调整都要改四处。<br>⚠ **设计侧追加一条硬约束（这条不写会破坏硬等价）**：**泉州的「晨」与 Cape Cod 的「雾」不能都塞进同一个状态机。** 前者是**时刻**（时段），后者是**天气**（状况）——语义本就不同，挤进同一状态机会让四地的状态集合不等价，硬等价即告破。<br>✅ **放行的设计侧形态**：**四地共用唯一的状态机「晨 / 昼 / 日落 / 夜」；Cape Cod 的「雾」改为正交开关**（独立 toggle，不占状态机位）。这样泉州的晨雾仍是"时段"，Cape Cod 的海雾是"开关"，两者互不污染 |
| **②** | **泉州截止时间点改为 `core α` 之前**（不是"阶段完成前"） | 泉州航标塔是 **core 层多格构件机制的第一个验证用例**。若拖到泉州动工后才拍板（D-1：石塔 vs 西式灯塔），多格构件的抽象会被泉州的具体实现反向污染，等做到塞舌尔的 3×3×2 巨石时就得回头改抽象。<br>→ **D-1 必须在 `core α` 之前锁定**，排产确定后立即落实。<br>✅ **已定案（2026-09-24）：A — 姑嫂塔式八角五层石塔，高 3 格与现有灯塔同高 → 直接复用灯塔的占位 / 碰撞 / 放置逻辑，改模型不改代码**（见 §7 D-1 与 §5 R-6） |

## 5. 风险提示

### R-1 · 松弛感被"目标"侵蚀（**最高优先级风险**）
**症状**：一旦加入连通判定 / 覆盖率 / 稳度，玩家会本能地开始**优化**。游戏从"随便搭搭"变成"要搭对"，P1 崩塌。

**四地点各有各的滑坡方向，必须逐个盯**：
- 泉州：玩家开始算"最短连通路径" → **红线：绝不显示数字、不设产率、不设效率**
- 塞舌尔：玩家开始比"谁堆得高" → **红线：不显示层数、不排名、不设纪录**
- Cape Cod：玩家开始追求"100% 覆盖" → **红线：不弹"100% 达成"，覆盖率热力图默认关闭且不给分数**

**通用预防**：
- 所有判定**只做视觉反馈**，不做数值、不做评分、不做失败态、不弹成就弹窗
- 「落成」的表现必须是**安静的仪式感**（光、声、材质变化），不是"恭喜达成！+100"
- 微光箭头 / 热力图等提示**默认关闭或可一键关闭**

### R-2 · 认知过载：一个地点只允许一个 `location_mechanic`
**症状**：玩家脑容量有限。同时学"悬挑 + 凿洞 + 观景位 + 承重"，休闲玩家 10 分钟内退出。
**预防**：
- 每个地点**严格限定一个新系统**。圣托里尼的"凿崖"与"悬挑"已是上限 → **凿崖必须延后到 1.1**（这也是减配方案的理由）
- 新规则教学绑定到**具体建材**（选中时才提示），不在开局弹教程
- **肌肉记忆零改动**（见 1.4 七项）

### R-3 · 隐性计时压力
**症状**：泉州的渔船、塞舌尔的象龟若做成"生产效率"，玩家会感到"来不及"。
**预防**：
- 泉州渔船动画是**恒定循环**，与玩家操作无关
- 泉州的**晨态**是**一个可自由切换的环境态**，不是定时衰减的雾（v2.3：晨态沿用昼档雾值，**雾本身不再有"晨雾"这个专属档**）
- 全部四地点**绝不做实时倒计时**

### R-5 · 机制撞车：泉州「连」 vs Cape Cod「照」
**症状**：四地点里只有这两款玩"光"。泉州的落成高光是"灯火次第亮起"，Cape Cod 的核心是"光网覆盖"。
**区隔（已在 2.3 表格给出）**：线 vs 面 / 结果 vs 手段 / 暖橙人居灯火 vs 冷白导航光 / 建筑师 vs 灯光师。
**排期区隔**：**Cape Cod 排第 4，与泉州拉开最大间隔**。
**宣发区隔**：泉州关键词「连 / 港 / 刺桐 / 灯火」；Cape Cod 关键词「照 / 灯塔 / 雾 / 光网」。

### R-6 · 灯塔重复：三个地点都有塔
**症状**：泉州航标塔、雾港原灯塔、Cape Cod 灯塔——三座塔，观感重复。
**缓解**：造型、配色、尺寸、角色必须**明显不同**：
- 泉州：**石构航标塔**（姑嫂塔 / 六胜塔式**八角五层石塔**，石基色 `b9bcad` + 陶砖 `c8856b`）——**它是"航标"不是"灯塔"，是链条起点，不发光锥**。<br>⭐ **已确认（2026-09-24）：石塔高 3 格，与现有灯塔同高 → 可直接复用灯塔的占位 / 碰撞 / 放置逻辑，改模型不改代码**（与美术侧结论一致）。D-1 的 A 选项实质上接近零成本
- 雾港原版：石砌小灯塔（纯装饰，不在四地点菜单内，或作为泉州的旧版资产退役）
- Cape Cod：高地白塔 / Nauset 红白塔——**光网主角，射程与仰角是核心数值，旋转光束**

> ⭐ **泉州航标改用石构塔而非西式灯塔**：① 姑嫂塔是宋元商船真实的抵港航标，文化身份顶级；② 一次性解决三塔撞车；③ 零新增色值；④ **高 3 格与现有灯塔同高，改模不改代码。**
> **D-1 已定案为 A（八角五层石塔，3 格高），锁定时间点见 §4.8.1 ②：`core α` 之前。**

### R-7 · 塞舌尔「叠」 vs 未来马耳他「砌」（候选池预留）
**症状**：两者都是"摆大石头"。
**区隔**：
- **叠**（塞舌尔）= **重心平衡**。天然圆石，无梁无柱，靠接触面与配重。动作是"往上摞、垫稳"
- **砌**（马耳他）= **构件承重咬合**。人工方石，有柱有梁，靠跨度校验。动作是"立柱、架梁、合拢"
- **排期区隔**：若未来做马耳他，**至少与塞舌尔间隔一款**
- **宣发区隔**：塞舌尔关键词「叠 / 巨石 / 平衡 / 花岗岩」；马耳他「砌 / 巨石神庙 / 五千年 / 架梁」

### R-8 · 存档与向后兼容
**预防**：
- JSON 增加 `location_id` 与 `schema_version`
- 跨地点导入给**明确提示**（"这是《塞舌尔》的存档，无法导入《泉州湾》"），不静默失败
- **同地点的版本升级必须能读旧档**（圣托里尼 1.0 → 1.1 加凿崖数据时，旧档要能正常打开）

### R-9 · 泉州的文化考据风险（**新增，本项目特有**）
**症状**：泉州是真实的世界遗产城市，涉及闽南文化、海上丝路、多元宗教。符号误用会引发争议，也会在当地玩家群体中失分。
**预防（设计侧立场）**：
- ✅ **只做民居与港市**：蚵壳厝、红砖古厝、燕尾脊、洛阳桥、航标塔、刺桐、榕树、簪花围
- ❌ **不做宗教建筑**：不开元寺、不清净寺、不草庵、不妈祖庙。泉州是"世界宗教博物馆"，宗教内容风险远大于收益
- ❌ **不做人名与历史叙事**：不出现蔡襄等历史人物，不做"史实关卡"
- ✅ 商店页与游戏内注明「**灵感来自福建泉州**」，并列出参考（洛阳桥、蟳埔蚵壳厝、闽南红砖厝）
- ✅ 音乐只用南音的**音色与音阶做氛围化编排**，不标榜"正宗南音"

### R-10 · 建材上限在垂直建造下可能不够
**预防**：圣托里尼建议提升到 **16000**，且**凿除量不计入**（减法不占额度，玩家会觉得赚到，是正向心理设计）。塞舌尔维持 12000 即可（巨石堆叠受稳度约束，数量天然有限）。UI 需明确显示"已用 / 上限"。

## 8. 交付摘要

- **四地点的动词落在四个不同空间维度**：连（水平·线）/ 凿·悬挑（垂直·向外）/ 照（水平·面）/ 叠（垂直·向上）——**无两款重复**。
- **泉州是本项目最大的一次"白捡"**：现有 13 建材色值天然就是闽南建筑（陶砖 = 红砖古厝、坡屋顶 = 红瓦、石基 = 蚵壳厝镶边、桥拱 = 洛阳桥），美术成本近乎为零，文化身份却是世界遗产级。
- **塞舌尔补上最后一种空间挑战**：砌（咬合）之外、悬挑（向外）之外，**堆叠是向上的平衡**；且花岗岩岛（大陆碎片）与圣托里尼火山岛地质成因天然对立。
- **成本分级**：**S 级 0 款**（证明不是换皮）· A 级 2 款（泉州 12–16 / Cape Cod 12–18）· B 级 2 款（塞舌尔 20–28 / 圣托里尼 25–35，v1.0 减配 20–26）。**含 core 底座（18，区间 17–20）：齐发地板线 ~74 人日（含 `MH-ENG-002a`）/ 满配 81–108 人日**。
- **首发门槛（运营定案配套）**：四地点统一适用 **M1–M6** 六项地板线（地形成型 / 动词成立 / 建材齐活 / 落成高光可达 / 引导完整 / **分享闭环（产品级）**），**任一地点未达线则整体延期**。<br>⚠ **首发债务 19–33 人日**：这不是可以砍的余量，也不是"更新节奏的内容源"，**必须在 1.1 之前偿付**，偿付能力取决于首发销量与现金流（口径更正见 §4.7.2 / §4.7.3）。
- **开发顺序**：**core 底座（与泉州并行）→ 泉州 → 圣托里尼（v1.0 悬挑，凿崖 1.1）→ 塞舌尔 → Cape Cod**。
- **最需警惕**：R-1 松弛感被目标侵蚀（红线，四地点各有滑坡方向）/ R-4 WebGL2 性能（**暖光灯是 core 层建材改造，四地点共用，已定案为共享光斑贴片**；Cape Cod 光锥方案评估中，结论决定排位是否重估）/ R-5 泉州与 Cape Cod 的"光"母题撞车 / R-9 泉州文化考据（只做民居港市，不做宗教建筑）。
- **⭐ 雾已降级（v2.3，用户拍板）**：雾从"需要数学达标的可调系统"降为**"每个地点调好的视觉常量"**——**只有昼档 / 夜档两档**；**四态昼夜作为光照概念完整保留**，晨与日落沿用昼档；**所有雾的数值判据作废**，改为观感判据（脚下 8 格内必须清晰）。泉州招牌画面由「晨雾锁港湾」改为「**晨光锁港湾**」。
