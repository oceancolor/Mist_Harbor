### 0.5 🔴 判据来源标注规则（**v1.2 新增元规则** · 读本文件前必看）

> **验收单里的每一条判据，都必须能追溯到「谁提的需求」。**
> （来源：`tech-feasibility.md` §12.3，engineering-lead 提出，team-lead 认可，本文件落地。）

**为什么有这条** —— 本次的失效模式是：

B-1 / B-2 / B-4 那三条数值判据**没有任何外部来源**，它们是工程推导过程中**自设的中间目标**；被写进验收单后获得了"看起来权威"的地位，**并反过来否决了撤销它们的那个决定**（验收员照着它们，会把"雾降级"判为不合格 —— 而降级本身就是用户拍板要求的）。

> ⭐ **完整形态**：**自设判据一旦落到任何带「通过/阻断」语义的文件里，就获得了超出其来源的权威。所以判据的「来源标注」必须跟判据一起走，不能只留在推导它的那份文档里。**

→ **本文件此后每条数值判据必须同时写明三样**：

| | 要求 |
|---|---|
| ① **来源** | `用户` / `设计` / `美术` / ⚠️ **`工程自设`** |
| ② **回源章节** | 具体文档 + 章节号（不许写"某文档"） |
| ③ **回问义务** | 若来源是 ⚠️ **工程自设**：**判阻断之前必须先回问一次**（问 team-lead / 主理人：这条还要不要），**不得由验收员直接判负** |

→ **验收员的操作义务**：看到「来源 = 工程自设」的判据没过，**第一动作不是"记个 FAIL 去修"，而是"停下来回问"。**
（现行条目里判负前必须回问的三处：**B-1′ 判据 ② 的 ≤0.006 上沿**、**B-3′**、**B-7 附加判据的灯:墙 ≥5:1**。**A-2** 与 **A-8** 同为工程自设，但已降级为记录/建议、不判负，故无回问义务。）
（同源留档见 §7 歧义清单第 7 条。）

> ⭐ **补充（v1.2.3 · team-lead 裁决）：说明性数值的界线**
> **说明性数值必须带回源，且一律不带「通过 / 阻断」语义。回源之前它只是解释，不是判据。**

### 🔴 检索纪律（v1.2.3 · 本轮踩出来的两个坑，读数值前必看）

> ⛔ **两个坑的共同点：不报错。第一个让人「搜不到」，第二个让人「搜到错的」—— 搜到错的更危险，因为搜不到至少会让人去问，搜到错的会让人直接照做。**

**① 怎么搜得到**：本项目**表格用中文行名、代码用英文属性名**。
- 找「**表里的数**」→ 搜**中文行名**：`环境光` / `太阳色` / `雾色` / `天空地平线`
- 找「**代码里的字段**」→ 搜**英文属性名**：`sunset_ambient` / `fog_density_day`
- 只用一个方向**必漏一侧**。（实例：工程侧曾搜 `ambient.*日落` **零命中** —— 因为那行中文写作「环境光（日落）」，单元格里不含 `ambient` 字样 —— 于是误判"该值没人给"，按错误前提算出 +71% 偏移。）

**② 搜到之后判断能不能用**：🔴 **认列不认数** —— 单看数字无法判断它是不是现行值，**必须看它在哪一行、哪一列**。
- **沿革段 /「上限 · 边界」列 → 默认不可引用，引用需主动举证**（不是"请谨慎判断" —— 谨慎判断是软约束，它把判断成本留给读者，而**读者恰恰是那个不知道自己需要判断的人**）。
- 实例 ×2（两侧文档各有一个同款坑，证明不是理论）：
  - `tech-feasibility.md` §1.4 沿革里圣托里尼 **0.0050** 是「可用 ρ **上限**」列（按已撤销判据反解），**不是现行值**（现行昼档 0.0015）—— **同一个数在两个语义里差 3.3 倍**；
  - `water-lighting-params.md` §5.1.1 沿革段「四地四态最终数值」表里 Cape Cod 日落 density **0.26**，与现行 `sunset_ambient` 的 0.26 **语义无关**（一个已作废、一个是现行值）。

### C-6 · 雾随 pitch 轻微变化 — ⚪ 记录项（**不是抖动** · v1.2 改写）

- **处置**：**正确行为。** 不要加节流、不要去"稳定"它、**更不要去"补偿"它**。
- ⛔ **与 v1.1 的区别**：v1.1 这里写的是"`begin/end` 跟着阻尼连续变化" —— 那条已随 **A-3** 作废。**现在这条说的是"距离变了所以雾变了一点"，是几何事实，不是实现 bug。**
- ⚠ 补充：若用的是 `pitch` 的 lerp 追随值（有阻尼），收敛期内雾会连续变化 —— 同样**正确**，不要去"稳定"。

### C-7 · 🆕 焦点永远有一层薄纱（**近场不恒零**） — ⚪ 记录项（**不是参数没调好**）

- [ ] 已知悉，已写进实现注释

- **事实**：`O(d) = 1 − exp(−ρ·d)`**没有 `begin`**，所以近场不可能是 0。泉州昼**焦点（48.0）就有 17.5%**。
- **为什么不修**：要焦点 ≤2% 得 `ρ ≤ 0.00042`，那时 35 格只有 3.2% —— **雾等于不存在**（§1.0.5 限制一）。这是模型的固有性质，**代价已在降级时接受**。
- **处置**：⛔ **不要试图"把近处调干净"**，也不要把它记成 bug。
- 🔴 **连带后果**：DEPTH 时代"把引导箭头限制在近场就不用担心雾"这条退路**因此失效** → **A-4 现在没有退路**。
- **必须写进实现注释的原话**：「焦点处有一层薄纱是 EXPONENTIAL 的预期行为，不要当 bug 修，也不要试图调干净。」

### C-8 · 🆕 泉州 vs Cape Cod 的 density 差 ≈2pp 属临界不可辨 — ⚪ 记录项（**不得因此判阻断**）

- [ ] 已知悉

- **事实**：泉州 0.0040 vs Cape Cod 0.0036，差值只有**焦点 1.6pp / 25 格 2.1pp / 35 格 2.3pp**。大面积均匀场的亮度觉察阈约 1–2%（Weber），**A/B 瞬切能察觉，静态并排读不出**。
- **处置**：⛔ **不得因此判阻断**（见 B-5 判据 2）；⛔ **不得为此去拉 density**（会把泉州推向糊、Cape Cod 推向无）。
- ✅ **性格靠色相不靠明度**：拉开雾色、或调雾色与天色地平线的关系（零成本，且比 density 有效得多）。
- ⛔ **更不要因此翻案回 DEPTH** —— 那需要用户重新拍板。

### M2 · 动词成立（**不是"能跑"，是"好玩"**） — 🔴 阻断项 🔶 判据草案

- [ ] 泉州「连」⬜ 圣托里尼「凿/悬挑」⬜ 塞舌尔「叠」⬜ Cape Cod「照」

- **门槛原文**：该地点独占的 `location_mechanic` 已上线并通过**手感验收**（不是"能跑"，是"好玩"）。
- ✅ **签字人已定（team-lead 裁决，2026-09-24）：手感验收由 Benja（用户本人）签字。**
  > 这是唯一一个没有仪器可读的门槛。**把它交给任何人都等于让它自动通过——只有付钱做这个产品的人有资格说它不好玩。**

**三层分工（按此执行，不要混）**

| 层 | 内容 | 谁判 | 性质 |
|---|---|---|---|
| **第 1 层 · 机器可读（QA 验）** | ① **2/2 自发完成闭环** | **QA（严守真）** | 客观 |
| **第 2 层 · 红线（QA 验）** | ② **是否破 P1 红线**（出现数值 / 评分 / 失败态即判负，**与"好不好玩"无关，独立判负**） | **QA（严守真）** | 客观 |
| **第 3 层 · 手感（人签）** | ③ 手感验收——不是"能跑"，是"好玩" | 🔶 **Benja 签字** | 主观 |

- **怎么验（第 1、2 层，QA 执行）**：
  1. 由 **2 名未参与该地点实现**的试玩者，**在无人指导、无教程墙**的情况下各玩 ≤ 10 分钟；
  2. QA 记录：① 是否**自发完成一次动词闭环**；② 过程中是否出现**数值 / 评分 / 失败态**；③ 顺带记是否**主动按 P 拍照**（P3 信号，**加分不判负**）；
  3. QA 把证据包（两份记录 + 回放/截图）交给 Benja，**不自行判定第 3 层**。
- **什么算过**（三层都要成立）：
  - 第 1 层：2/2 自发完成闭环；
  - 第 2 层：零数值反馈、零失败态（**红线，破了就负，不看第 3 层**）；
  - 第 3 层：🔶 **Benja 签字确认"好玩"**。
- **失败怎么办**：
  - 第 1 层不过 → 查教学绑定（新规则提示是否绑到具体建材）；
  - 第 2 层不过 → **判负，直接回设计侧**；
  - 第 3 层不过 → **回设计侧重定动词本身，不得靠加数字、加目标、加进度推进度。** 加了数字就不是这款游戏了（设计支柱 P1）。
  - ⚠ **任何一层不过，都不得由 QA 或设计侧代签放行。**
- **证据留存**：两份试玩记录（是否闭环 / 是否有数值反馈 / 是否拍照）+ 证据包交付记录 + **Benja 的签字（书面，写明地点名）**。

> ⚠ **QA 立场（已由 team-lead 裁决采纳）**：这条的判据本身不可客观化。"好玩"没有仪器可读。**QA 只出证据包、只判前两层；第 3 层必须由 Benja 签字 —— 不能由 QA 打了勾就算数。** 见 §7 歧义清单第 4 条。

### M6 · ⭐ 分享闭环（**产品级，非地点级**） — 🔴 阻断项

- [ ] 通过（**只做一次，四地点共用**）

> ⚠ **M6 是必补项，不是优化项。** 本产品的商业循环是"内容消耗型"——玩家买的是**内容量 × 可分享性**。
> 现状：**P 键存在但拍完无出口，闭环是断的。**
> **不做则整体不达线**：M1–M5 全部白做 —— 玩家拍了照但传不出去，"可分享性"就转不成真实曝光。

- **怎么验**：
  1. 按 P 进入拍照模式，拍一张；
  2. 找出口 UI：拍完**必须能看到**分享出口（保存到相册 / 复制到剪贴板 / 一键导出分享图，**至少一个**）；
  3. **实测这个出口真的能出图**（不要只看按钮在）：点它，确认文件真的下载了 / 剪贴板真的写入了 / 分享图真的生成了。
- **什么算过**（客观）：
  - 至少一个出口**实测成功**；
  - 出口 UI 在拍完后可见（不需要玩家猜）；
  - **失败路径有明确提示**：Web 端剪贴板在非 HTTPS 或权限被拒时必须给出明确失败提示，**不得静默失败**（静默失败 = 玩家以为分享成功了）。
- **失败怎么办**：🔴 **本条没有"降级到下一版"的选项** —— 它是产品级门槛。缺它 = 整体不达线。补完做一次端到端实测（拍 → 出 → 真的拿到图）。
- **证据留存**：出口 UI 截图 + 实际产出的图片文件 / 剪贴板内容确认。
