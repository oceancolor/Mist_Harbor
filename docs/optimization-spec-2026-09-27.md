## §1 摄像机必须能到地平线（侧视全景）

**现状**：正交相机 zoom 10-48、轨道半径 48；`_pitch_floor()` 与 zoom 联动——zoom 越大最低俯角越高
（zoom 48 → ≈17°），永远到不了"海平线居中的侧视全景"。

**根因**：俯仰下限的存在理由是"画面下缘光线不能看穿场景"。但看穿场景是因为**海只有 180×8×180 的盒子**；
只要海足够大且无穿帮，下限就没有物理必要。R-ENG-22 的 WATER_TOLERANCE=8 是在"小水盒"前提下的补丁，
治标不治本——🔴 本条与 §2 联动，**单独放宽 WATER_TOLERANCE 不算解决**。

**方案**：
1. 以 §2 的"无限海面"为前提，`_pitch_floor()` 放宽到 **pitch ≥ 0 对全部 zoom 可用**（海平线可居中）；
2. zoom 与高度联动保留：只防"看到天空球底下/盒底"这类硬穿帮，不防"看到海面"；
3. 相机 near/far 与 zoom 联动核查（far ≥ 天空半径 + 轨道半径 + zoom）。

**验收**：zoom 48 + pitch 0° 时，画面下半是连续海面直到海平线，海平线在画面内清晰成线；
qa 参数 `pitch=0&zoom=48` 截图 + 像素探针确认海平线上下色差（天/海两段色带）。

## §2 海必须比可建场景大得多——任何 FOV/机位都不穿帮

**现状**：水盒 240→180×8×180（±90），天空球半径 150，camera.far=300。
拉远 + 低角度时：水盒边缘可见、盒体被切出**切面**（侧壁与顶面色带断裂）、盒外露天空球下半球的"远海色"。

**根因**：用"有限盒子"模拟"无限海"。正交相机的视野随 zoom 线性扩大（zoom 48 → 半宽 ≈43 格），
盒子和球总有一天被看穿——**尺寸竞赛没有赢家，必须按"无限"设计**。

**方案**（两层海 + 尺寸核查表）：
1. **近海**：跟随场景的高细节水面（现有破波/浪花/光带 shader），尺寸 ≥ 可建区 + 风景带的 2 倍；
2. **远海**：一个**超大平面**（建议 4000×4000 或按 far 覆盖），与近海同基色、同雾、
   无浪花细节（或 shader 内按离相机距离淡出细节）——近远海衔接处用色带渐变，不允许出现几何边界线；
3. 近海盒体**取消可见侧壁**：改用"只渲染顶面 + 远海承接"或把侧壁做进远海色；
4. 尺寸核查表入代码注释：`远海半径 ≥ camera.far`、`天空球半径 ≥ 远海半径`、
   `camera.far ≥ 天空球半径 + 轨道半径 + zoom/2`——三者推导写死，任何人改一个数必须核对另两个；
5. 天空球下半球保留"无限远海面"渐变兜底（R-ENG-23 保留）。

**验收**：qa 机位矩阵（zoom 10/24/48 × pitch 0°/10°/30° × 四地点）24 张截图，
像素探针确认：① 无任何几何边界线（画面内不允许出现与岸线/海平线无关的直线色断）；
② 最低机位画面 100% 被水色或地形覆盖，无盒底/切面色。

## §3 天空盒与日/月/星（方向渲染，弃屏幕空间公告板）

**现状**：R-ENG-26 的"海平线锚定屏幕空间公告板"是正交相机下的妥协——太阳/月亮位置是**画出来的**，
不是天上"真的有个太阳"，导致：只有特定机位看得到日落夕阳；月亮/星星与场景无空间一致性；无法驱动海面反射。

**根因**：把"天体在哪"和"屏幕上画在哪"耦合了。正确做法是让天体存在于**方向空间**，
每个像素沿真实视线方向采样天空——正交相机也能正确做到（每像素视线方向不同，screen-space 依赖是伪命题）。

**方案**（迁移到 Godot 自定义 Sky Shader）：
1. 把程序化天空（渐变/云/远景剪影/星点/日月）迁到 **WorldEnvironment 的自定义 Sky shader**：
   sky shader 天然拿到每像素视线方向 `EYEDIR`，天体 = `dot(EYEDIR, SUN_DIR)` 的圆盘+光晕，
   **零视差、任意机位正确**，现存 sky sphere MeshInstance3D 及其 cam_pos/cam_axis 每帧回写全部删除；
2. 日落：太阳方向即可见方向——落日悬在西方海平线上，任何朝西的机位都看得到（含侧视全景）；
3. 夜间：**满月**（先不做月相）+ 星点层（现有 sky_tex B 通道迁移），月亮方向 = 夜态光方向；
4. **海面菲涅尔**：水体 shader 加视角依赖项 `fresnel = pow(1 - dot(view_dir, up), k)`——
   掠射角反射天空色（日落金橙/夜暗蓝/昼天蓝），近垂直角保持水体本色；
   与现有日/月光带（reflect 镜面项）叠加，日落时"金光大道"从太阳脚下铺到相机前；
5. 现有屏幕空间公告板代码与 `_process` 里的 cam_dir 回写在迁移完成后**删除**（不留双轨）。

**验收**：
- 任一朝西机位（qa `yaw`+`pitch=0`）日落态：太阳圆盘悬于海平线上方，海面出现从太阳向相机的金色反光带；
- 夜态任意机位：满月 + 星点可见，海面月光带；
- 菲涅尔：低角度侧视时远海明显偏天色/日光色，正俯视时偏水本色（像素探针比对两个机位的远海色差）；
- 四地点 × 四态截图回归：天空迁移不破坏现有四态配色。

## §5 色彩矫正（参考：蔡尔德·哈萨姆新英格兰海岸）

**总原则**：当前整体**偏灰**。哈萨姆的要点：灰不是脏——是**高明度、低饱和但色相明确**的蓝绿紫灰，
阴影偏紫、受光偏暖玫瑰；海是蓝绿交织而非灰绿。每个地点先定"海水三段色 + 天空两段色"目标值，
改完用像素探针实测 RGB 对表，不允许凭感觉。

**各地目标**（起始值，探针实测后微调 ±10%）：

| 地点 | 问题 | 海水三段（深→浅）目标 | 其他 |
|---|---|---|---|
| 泉州 | 海水太绿 | `#1D5E93` → `#2E7BA8` → `#4FA3B8`（蓝青，去绿相） | 天空保持现有暖调 |
| 圣托里尼 | 缺"心目中的地中海蓝" | `#1E56A8`（深钴）→ `#2E86C8` → `#41B8CE`（近岸绿松石）——**饱和钴蓝，不是灰蓝** | 白屋受光面提亮，红褐崖保持 |
| 塞舌尔 | 缺泻湖透明感与深浅组合 | 泻湖 `#8FDFD4`（透明青）→ `#3FB0BC` → 外海 `#17709E`——**深浅突变要分明**（礁盘边缘线） | 泻湖环内可加浅色"沙底透出"效果 |
| Cape Cod | 太灰 | `#4A7E8C`（灰蓝绿，哈萨姆海色）→ `#6FA8AC`；**受光面带暖玫瑰灰** `#C8A898` | 天空地平线加哈萨姆式玫瑰暖灰 `#D8B8A8`；沙滩暖白 |

**验收**：四地点昼态截图 → 像素探针取海水三段/天空/沙滩的平均 RGB，逐项对表上值（±10%）；
日落/夜态不回归（现有 tint 机制自动跟随）。
