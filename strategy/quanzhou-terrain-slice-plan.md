## §0 这一刀要证伪什么

**一句话**：玩家用同一套通用语法乱搭，出来像不像泉州湾。

- 证伪了（不像）→ 「乱搭也像」这条不成立，**立刻改方向**，不要往下做第二、第三个地点。这是本切片最大的价值。
- 成立了 → 「geo meta 三层（外观 / 构件子集 / 规则覆写）」这套架构被证实够用，**再向其余三地铺开**。

**范围严守 Q-9 的拍板：只做地形层。** 生长物与人造物在切片里只做「最低限度接入」，不展开规则。

## §2 S0 · geo meta 数据结构（泉州初版）

只填三项，够驱动切片即可。**字段表回源 `geo-meta-and-build-grammar.md` §3**，本文件不复制整表。

```gdscript
# 建议落点：resources/geo_meta_quanzhou.tres（与 LocationProfile 同目录）
island_outline:
  lobes: 3                  # 椭圆叶瓣数（承接现 reset() 的三个距离场）
  lobe_scale_range: [0.7, 1.4]
  noise_frequency: 0.12     # 沿用现值
  shore_jitter: 0.18        # 沿用现值（0.95 + n * 0.18 中的 0.18）
land_distribution:
  land_ratio_range: [0.30, 0.50]     # 🔴 工程自设，待调
  min_landmasses: 2                  # 主陆 + ≥1 屿
  mudflat_band_ratio: [0.12, 0.30]   # 滩涂环带占陆地比 🔴 工程自设，待调
palette_subset:
  terrain: [stone, grass]     # 注：wood/brick 已归 built（Q-13 已复核通过）
  growth:  [tree]
  built:   [wood, brick, cottage, lamp]
```

⚠️ **两个字段值是我设的，不是查到的**：`land_ratio_range` 与 `mudflat_band_ratio` 的区间。理由：现有 `reset()` 的实际产出我未做统计，这两个区间是**先给一个可跑的初值、用 S1 的 20 seed 实测回填**。**别把初值当结论。**

## §3 S1 · 受限生成（这一刀的核心）

### 3.1 关键发现：现 reset() 已经暗含「湾 + 屿 + 滩涂」

读 `world_model.gd:148-180` 现值，三个椭圆距离场 `a/b/c` 取 `min`：

| 泉州特征 | 现代码里的对应物 | 行 |
|---|---|---|
| **屿** | 三个分离椭圆 → 天然产生多个陆块 | 160-163 |
| **湾** | 椭圆**之间的凹部**（未被任一椭圆覆盖的水域） | 同上 |
| **滩涂** | `kind = "grass" if distance < 0.85 else "wood"` → **`wood` 环带正是岸边/滩涂带** | 175 |

→ **真实增量是「参数化 + 加硬约束」，不是重写生成器。** 这一条要记账清楚：`terrain_generator.gd` 本体**已在预算内**（`engineering-eval-st-d2-fog.md` §维度 1），别重复计入。

### 3.2 硬约束（geo meta 写死，不满足就重摇）

四条，全部**可在生成后便宜地算出**：

| ID | 约束 | 判据（可计算） | 值来源 |
|---|---|---|---|
| **C1** | 有屿 | 陆地连通分量数 ≥ 2 | 形制要求「湾+屿」 |
| **C2** | 有湾 | 水域格中「4 邻至少 3 个是陆地」的格子数 ≥ 8 | 🔴 工程自设，待调 |
| **C3** | 有滩涂 | `wood`（岸边带）格数 / 陆地格数 ∈ `mudflat_band_ratio` | 🔴 工程自设，待调 |
| **C4** | 海陆比 | 陆地格 / 总格 ∈ `land_ratio_range` | 🔴 工程自设，待调 |

**C2 是本切片最值钱的一条**：「4 邻至少 3 陆」= 三面被陆地围住的水 = **内湾**。这条判据把「湾」从主观印象变成了可计算量，也是 M1 能不能保住的技术抓手。

### 3.3 重摇（Q-8 口径：系统内部行为，玩家看不见）

```
seed = 开局随机
for attempt in range(MAX_RESEED):        # MAX_RESEED = 40 🔴 工程自设
    生成地图(seed)
    if C1..C4 全过:
        交给玩家; break
    seed = 下一个
else:
    🔴 报错，不交给玩家（宁可报错也不给不合格地图）
```

存档仍记 `seed`（现 schema v1 已有）+ 新增 `geo_meta_version` / `generator_version`（回源 §6.3）。

## §5 S2 · 地形顶点色交融

- 地形件是 cube 且已合并 ArrayMesh → **顶点色插值**就能出融合边界（回源 §6.1：理由不再是省面数，而是变体数量会推高顶点总量与重建耗时）
- 交融宽度作为 **geo meta 覆写项**（L3 白名单第 1 项示例）——「乱搭也像」正是靠这类参数被地点改写
- 切片只做 **stone ↔ grass ↔ wood** 三者的两两过渡

## §6 S3 · 生长物聚丛件（只做一个）

**选件建议：刺桐。** 理由三条：
1. 回源 `location-gameplay-design.md` §3「**灵魂植物 · 泉州 = 刺桐 / 垂榕**」——刺桐是泉州的城市符号（刺桐城），用它验证「像不像泉州」最直接
2. 乔木的聚丛语义最清晰（单株 → 丛 → 林），能干净地验证「自动聚丛」
3. 滩涂带的芦苇/红树林**留到下一刀**——它需要先有潮间带语义位，本切片不展开

**机制**：玩家放**个体**，系统按邻域与密度**自动聚成丛**（形态解析出来，**不进存档**；撤销单元 = 个体）。回源 §5.3。

## §7 S4 · 运行时实测（Q-12 的输入，切片必须出数）

Q-11 解除面数硬顶后，**接棒的运行时预算还没有口径**。切片阶段必须测出这三项，作为 Q-12 的提案依据：

| 指标 | 测什么 | 怎么测 |
|---|---|---|
| **顶点总量** | 全岛合并 ArrayMesh 的顶点数（现状 vs 切片后） | `rebuild()` 后读 mesh 统计 |
| **单次 `rebuild()` 耗时** | 放置一次触发重建的 ms | 现有 ~12,000 方块上实测 |
| **几何数据体积** | Web 首屏要下的几何量 | 导出后统计 |

→ **R-D 已升为首要风险**（回源 §8）。这三项不出数，「顶点色 vs 几何变体」的取舍就只能靠猜。
