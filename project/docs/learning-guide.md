# 雾港造物记 · 课堂与自学指南

## 这是什么

这是一个原创的单人 3D 自由建造样板，不是商业游戏复刻。你可以在有限海岛上堆叠地形、房屋、屋顶、桥拱、灯塔与花园。没有资源焦虑、战斗或胜负计时。完整工程用于拆解与 Remix，不把完成样板看作完成个人作业。

推荐环境：Godot **4.4.stable**；编辑资产使用 Blender **4.2+**。浏览器需要 WebGL 2，建议桌面或横屏平板。Web 导出采用 GL Compatibility、单线程。Godot 的导出模板必须与引擎版本一致。

课时安排：下述八课合计 285 分钟，最终反思 20 分钟，共九项必修任务 305 分钟；再预留环境准备 25 分钟、演示评审 30 分钟，总计 **360 分钟**。第十项分块世界 Remix 是 **额外 90 分钟选修**，不计入 360 分钟。机器可读口径见教程包根目录 `learning_tasks.json` 的 `schedule`。

## 第一课：观察与建造（20 分钟）

1. 用 Godot 导入本目录的 `project.godot`，运行 `main.tscn`。
2. 用左键放置小屋，按 R 改入口方向；按 B 切换拆除模式。
3. 右键拖动环绕，WASD/中键平移，滚轮缩放，F 回到岛屿。
4. 使用撤销与重做，观察“世界状态”而不是只看工具栏。
5. N 切换昼夜，P 隐藏界面拍照，Esc 返回。
6. 保存后刷新浏览器；通过“作品管理”导出 JSON 作为跨设备备份。

**交付**：`docs/play-observations.md`，记录一次成功、一次被拒绝的操作及原因。六项岛屿小挑战只是本地自练提示；种子里原有的建筑不计入你的新增成果。

## 第二课：网格、法线和空间占位（35 分钟）

阅读 `scripts/world_model.gd`：`cells` 保存每个建材原点的类型与旋转；`occupancy` 保存高模型占据的所有格子到原点的映射。一座高三格的灯塔仍只有一个建材原点，但不能让其他格子穿过它。

阅读 `scripts/build_world.gd` 的 `pick`：

- 射线先命中场景碰撞体；根据命中点与法线决定“拆哪一格”和“在旁边哪格建造”。
- 水面没有可挖地形时，使用固定水面平面给出地基格。
- 预览鬼影不带碰撞，避免下一次射线先撞上预览自己。
- 草地/石块使用合并网格，只输出外露面；复杂模块用 GLB 与简单占位碰撞。

**交付**：`docs/grid-design.md`。画出命中顶面与侧面时的坐标推导；解释为什么世界边缘、重叠和半空位置会被拒绝。教师需要看推导与现场演示，文件存在并不代表答案正确。

## 第三课：原创聚落（35 分钟）

从“空白群岛”开始或延伸示范村落。新建三座房、连续栈道或桥拱、一座灯塔和花园。水面可以打地基，空中格子需与已有块相接；当前规则是创造模式，不模拟结构倒塌。

**交付**：`submissions/my-island.json`、`docs/build-notes.md` 和日夜截图。请说明路线与地标如何组织空间，而不是只堆数量。路径可通行性由你演示，本样板没有自动通行评分器。

## 第四课：Blender 模块资产（60 分钟）

打开 `art/mist-harbor-kit.blend`，在副本中制作一个原创长椅、拱窗或凉亭。八种自带模块均由 `art/generate_harbor.py` 确定性生成，资产来源与实际面数见 `assets/models/manifest.json`。

资产规范：

- 单位为米；一个格子的 X/Z 占地约为 `1 × 1`。Godot 使用 Y 向上，Blender 使用 Z 向上，glTF 导出负责转换。
- 模型原点在底面中心；不要把模型留在工作室展示用的偏移坐标上导出。
- 应用缩放，检查朝外法线；尽量复用少量材质，不用外部贴图 URL。
- `data/palette.json` 的 `height` 是逻辑占格整数，不是模型精确米数：小屋/屋顶/桥拱/花坛占 1 格，树/路灯/风车屋占 2 格，灯塔占 3 格。
- 桥拱的视觉模型有拱洞，但逻辑占位和拾取碰撞仍是整格；不能把看见的拱洞当成已实现角色通行。当前没有步行角色，桥梁作业只检查拓扑连续性与净空设计。
- `mesh` 填 GLB 文件的无扩展名部分；`id` 为唯一建材 ID；类别只能沿用地形/建筑/自然，或同步修改分类 UI。
- 放在 `assets/models/extra-module.glb`。Godot 运行时只需要 GLB；`.blend` 被 `art/.gdignore` 排除，不会隐式调用 Blender。

**交付**：新 GLB、`docs/module-notes.md`（尺寸、三角面数、来源、导入截图）以及修改后的建材表。原模板测试对基线数量有断言；合理扩展时请把数量断言调整为“原有 ID 仍存在 + 新 ID 唯一”，不要删除行为断言来凑通过。

## 第五课：撤销与测试（35 分钟）

命令历史记录格子原点的 `before/after` 状态，撤销/重做都走相同的底层变更方法。新的操作清空重做分支；历史最多保留 160 项。

在项目目录执行真实 Godot 测试（将 `godot` 换成你的引擎可执行文件路径）：

```sh
godot --headless --path . --script res://tests/test_world.gd
godot --headless --path . --script res://tests/smoke_scene.gd
```

Windows PowerShell 的带空格路径使用调用运算符：`& "C:/你的路径/Godot.exe" --headless --path . --script res://tests/test_world.gd`。

前者验证状态、空间占位与存档；后者验证真实资产、场景与 UI 回调。两者都不能代替“鼠标真的点到正确格子”的浏览器实测。

**交付**：原始输出 `submissions/test-output.txt`、新增一个边界案例及 `docs/control-test.md`。不要伪造退出码，不用修改测试预期隐藏程序缺陷。

## 第六课：安全存档（35 分钟）

本地保存位置为 `user://mist_harbor_world_v1.json`；Web 版依赖当前浏览器的持久化存储。清理网站数据、无痕模式或存储配额不足都可能影响保存，请用 JSON 导出备份。

`load_document` 先验证整个存档，全部通过后才替换当前世界。检查：版本、游戏 ID、数量、整数坐标、边界、建材白名单、高模型重叠、旋转及统计范围。导入不是执行程序，不能由存档指定外部资源路径。

在自己导出的文件副本里测试：无效 JSON、未知版本、小数坐标、超界、重复格子和超大文本。每次都保留前后截图或状态摘要，证明拒绝后作品没变。

**交付**：`docs/save-review.md`，由教师确认。合法存档的往返恢复与非法输入的原子拒绝同样重要。

## 第七课：性能与取舍（40 分钟）

看 `build_world.gd` 的外露面剔除。当前样板为了可读性按修改重建有界网格，适合小规模教学，不是无限体素引擎。

在同一设备、浏览器版本、视角和窗口尺寸下，测量默认岛、增加 100 件、增加 500 件的帧率、draw call 与一次修改耗时。建议探究：缓存微缩地图、局部 chunk 重建、重复装饰使用 MultiMesh。先复现瓶颈再优化，不直接把更换设备当优化。

**交付**：`docs/performance.md`，记录条件、原始数据与一个可重复的改动。软件 WebGL、低端设备和大量夜间灯光可能较慢，不承诺所有设备 60 FPS。

## 第八课：导出与分享（25 分钟）

重新导入资源，运行测试，使用 `export_presets.cfg` 中的 Web 预设导出。需要匹配的 Godot 4.7 Web 模板。主要产物为 `build/index.html`、`index.js`、`index.wasm`、`index.pck`（导出到工程目录之外，避免编辑器把产物当资源导入）。

```sh
godot --headless --path . --editor --import --quit
godot --headless --path . --export-release Web ../build/index.html
python -m http.server 8184 --directory build --bind 127.0.0.1
```

本机可以访问 `http://127.0.0.1:8184`；远程域名或局域网 IP **必须使用 HTTPS**，以满足 Godot 4.4 的安全上下文要求。不能直接双击 `index.html` 的 `file://` 路径。单线程版不要求 SharedArrayBuffer；如果改为线程版，需同时正确配置 COOP/COEP。

**验收分层**：文件存在 → 引擎导入 → headless 运行 → 实际 WebGL 渲染 → 真实输入 → 保存刷新 → 导入导出。只有前两项成功不能声称“游戏已完全可玩”。
