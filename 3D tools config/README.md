## 2. 本项目的判据权重（为什么通用第三方评测不适用）

**通用评测里「贴图 / PBR」占一维且各家都在卷；本项目资产画像把这一维归零。**

回源 `prompt-library.md` §2.4（美术侧现行口径）：材质在 Godot 端统一改写为 `flat shading` + 顶点色 / 单色 albedo，**无贴图**；负面提示词已全库统一压掉写实贴图。

因此本项目判据排序为：

| 序 | 判据 | 权重 | 回源 |
|---|---|---|---|
| 1 | **生成端能否一次把面数钉进预算**（全库硬顶 ≤ 600，蕨类 < 200） | 最高 | `prompt-library.md` §2.4；各地 spec 面数预算列 |
| 2 | 中文具名构件的语义还原（燕尾脊 / 蚵壳厝 / 骑楼） | 高 | `quanzhou-spec.md` §3.2 |
| 3 | Godot 4.4 直导链路（GLB / Y-up / 原点底面中心） | 中 | 本文件 §7 |
| 4 | 单次成本（34 资产 × ≤3 次的量级） | 中 | `tool-connections.md` §6 |
| 5 | 几何精度上限 / 拓扑质量 | **低**（低多边形风格下几乎无关） | — |

> 🔴 **判据 1 是唯一「必须一次命中」的**：面数超标只能回炉重生成或额外减面，直接吃额度与工时。
> 图示结论：**只有 Tripo 的 `face_limit` 是文档化、可一次命中的生成端参数**；混元 LowPoly 下限 3000 面，为本预算的 5–15 倍，必须再过一轮减面；Meshy 与 Rodin 均未见公开生成端面数目标。
> 📌 面数红线为**美术侧现行值**（`prompt-library.md` §2.4），不是工程侧自设。

## 3. 分路由选型（v1.2 建议主路线）

> ⚠️ **本节路由为工程侧自设建议**（依据 §2 判据推导）。按项目纪律，**工程自设的判据在判「阻断」前必须回问一次**；路由本身不自带通过/阻断语义，只决定「先试哪条通道」。

| 路由 | 资产画像 | 主通道 | 对照通道 | 面数落地方式 |
|---|---|---|---|---|
| **A** | 中式具名构件（燕尾脊 / 蚵壳厝 / 红砖古厝 / 骑楼等） | **混元3D**（中文直解，绕开英文中转译失真） | Meshy **image-to-3D**（喂概念图，同时是唯一吃到 Meshy 7.1 的路径） | 混元出 3000 面起 → 必过 §6 Blender 减面 |
| **B** | 通用低多边形件（道具 / 植物 / 地形 / MultiMesh 密铺件） | **Tripo text-to-3D**（无贴图 10 积分） | — | **`face_limit` 直接给预算值**，必要时加 `smart_low_poly` +10 |
| **C** | Hero 造型件（需反复迭代、造型要求高者） | **Meshy 7.1**（Smart Topology 分件几何 + remesh） | Tripo | remesh 后处理 + §6 校验 |

三条路由**汇合到同一下游**：§6 Blender headless ③B 批量 QA → ④ 色值校验 → Godot 导入 → ⑥ 验收归档。三家输出均为 GLB，切换成本低。

### 3.1 B 路由的额外杠杆（待试产验证）

社区 Tripo MCP v1.1.0 的 `stylize_model` 支持 **minecraft / voxel / lego / voronoi** 四种风格化 —— 与 `prompt-library.md` §2.2 风格前缀里的 "chunky simplified stylized shapes, miniature diorama style" 高度同向。

> ⚠️ **尚未试产验证**，属待验证候选。**不进任何判据**，只在泉州试管线里顺带 roll 一次看效果。

### 3.2 风格前缀纪律不变

`prompt-library.md` §2.1 铁律继续有效：**所有资产共用同一段风格前缀，逐条只替换主体描述，前缀一个词都不许改**。三路由分引擎不改变这条 —— 若某引擎风格跑偏，**只改主体描述或重新 roll，不改前缀**。

### 3.3 同一资产跨引擎对照的成本约束

同一条 prompt 跑两个引擎 = **成本 ×2**，且各引擎对同一段前缀的响应不同。因此**只在 A 路由做双引擎对照**（中式构件语义是真实风险点）；B / C 路由单引擎 + 面数兜底，**不做全库双跑**。

### 3.4 Rodin（Hyper3D）：评测保留，不划出本轮 scope

- **状态**：🟡 **评测保留** —— Benja 2026-09-26 拍板：暂不划出，保留进一步审视资格，**并将购买 API key 用于评测**。

- **保留审视的理由**：① pay-by-result（先预览、确认满意再扣费）与本项目「择优」流程天然契合，失误不烧额度；② 多图输入 + 3D ControlNet（bbox / voxel / point cloud 条件）是**唯一可用几何约束框住格数**的通道，若 B 路由靠 `face_limit` 仍不稳，这是潜在替代；③ 拓扑质量口碑最好，若后续要 hero asset 值得回头看。

## 5. 管线流程（每个资产六步 + 可选 Blender 批量段）

```
① 取提示词（prompt-library.md 对应条目，风格前缀原样带）
   → ② 分路由生成（按 §3 选 A/B/C 通道；A 路由可用概念图走 image-to-3D，
        且这是 Meshy 唯一能吃到 7.1 引擎的路径）
   → ③ 压面数（Tripo face_limit 直接给预算值 / Meshy remesh / 混元必过 Blender 减面；
        对照 spec 面数预算，如蕨类 < 200、海椰子 < 600）
   → ③B（可选·整批统一做）Blender headless 批量 QA：批量减面到预算线 + 面数自动校验
        + 法线/轴心修复 + 批量导出 GLB（见 §6；单件试产时跳过）
   → ④ 色值校验（对照 spec hex 表；AI 贴图色偏则用 retexture 修，仍偏则改用顶点色/材质球在 Godot 端覆写）
   → ⑤ 导出 GLB → Godot 导入（场景约定见 §7）
   → ⑥ 对照验收表（prompt-library.md 末节）打勾归档
```

## 6. 可选 · Blender headless 批量/QA 阶段（非关键路径，2026-09-25 Benja 拍板增补）

**定位**：本管线是「AI 直出 GLB → Godot」的轻管线，**Blender 不做每资产强制步骤**；但当批量规模上来或 AI 导出质量不稳时，用一个 headless Blender（`bpy`）批处理脚本做整批 QA，效率远高于在 AI 工具 UI 里逐件手动处理。

**触发条件（满足其一即启用）**：
1. 单批待处理资产 **> 10 件**（如泉州组首批 18 件）；
2. AI 导出出现**坏网格**（反面法线、非流形、原点/朝向不对、比例失真）；
3. 需要 **LOD 或碰撞网格**（本体重构等英雄资产）；
4. 需要输出**面数校验报告**作为验收证据（对应验收表「面数预算」列）；
5. **（v1.2 增补）走 A 路由的任何资产 —— 混元 LowPoly 下限 3000 面，必然超预算，必过本段**。

**批处理脚本职责（QA 四件事）**：

| 职责 | 做法 | 验收口径 |
|---|---|---|
| 批量减面 | `bpy` decimate modifier 逐件压到该资产面数预算（预算表从 spec 导出成 JSON 供脚本读取） | spec 面数预算列（硬顶 ≤ 600） |
| 面数自动校验 | 逐件统计三角数，超预算的**拒收并记日志**，不进下一环节 | 同上 |
| 网格修复 | 法线重算（`normals_make_consistent`）、非流形修复、原点移到底面中心、Y-up 校正 | Godot 导入零修正 |
| 批量导出 | 统一命名 `loc_{地点}_{类别}_{名称}.glb`、纯几何单件 < 30 KB | art doc §11.3 |

**调用方式（无 MCP，走命令行）**：
```
blender --background --python qa_batch.py -- <输入目录> <输出目录> <面数预算表.json>
```

**与六步的关系**：③B 是整批统一做的段（不是每件资产生成后立刻过），插在 ③ 与 ④ 之间；单件试产、小批量、AI 直出质量稳定时可整段跳过。**Blender 里不做的事**：雕刻、重拓扑、UV 展开、烘焙、绑定——本项目资产画像（低多边形/纯色/无贴图/无骨骼）刻意避开这些，不要回潮。

## 7. Godot 4.4 端约定（来自 `Dev Driven/tech-feasibility.md` 与 `godot-web-perf.md`，此处只列管线相关）

- **Web 端 Compatibility 渲染器**：不要 PBR roughness/metallic 贴图依赖——材质在 Godot 端统一改写为 `flat shading` + 顶点色/单色 albedo；生成时用负面提示词压掉写实贴图（prompt-library 已含）
- **MultiMesh 密铺件**（蕨类/海滩草丛/微光箭头等）：单独 GLB，单实例几何尽量 < 300 面
- **光效不进模型**：暖光灯、灯塔本体**不含任何光效几何/发光材质**——光斑贴片在运行时加（A-1 材质族：`unshaded` + `fog_disabled` + `blend_mix`）
- **坐标**：导出 GLB 保持 Y-up；单资产原点在底面中心（摆放系统 `_add_prop()` 的约定）
- **单资产面数红线**：以 spec 各清单的面数预算列为验收硬口径；超标的先进 remesh，压不到的回炉重生成，不进 Godot
