# 雾港造物记 · 用 AI Agent 从 0 做出可发行游戏

> 一句话：这是一套**边做边学**的长教程。你不会只读到概念，而是跟着 48 个有序任务，
> 用 CodeBuddy（Agent）+ Godot 4.7 + Blender + 两个远程 MCP 服务，把《雾港造物记》
> 从空目录一路做到 **Web / Windows 双端可发行成品**，并理解每一步为什么这么做。

## 1.5 运行环境：云端 agent（web-cb）为主，本地可选

本实训的正式环境是**云端 agent（web-cb）**——它会按不同 PBL 项目，在云端预先搭好
**MCP 服务、skill、托管平台，甚至基础代码仓库**。学员进来就能开工，**不需要**自己安装引擎、
配置 MCP 或创建仓库。

| | 🌩 云端 agent（web-cb，默认） | 🖥 本地路线（可选：离线、可改引擎） |
|---|---|---|
| 引擎 / Blender | 平台镜像内置 | 自己装，路径写 `tools.json` |
| MCP 服务与令牌 | 平台预置并托管 | 自己改 `mcp.json`、自己保管令牌 |
| 代码仓库 | 平台按项目预建 | 自己 `git clone` |
| 跑测试 / 看画面 | 平台入口，底层同一套命令 | `python tools/dev.py test|run` |

**既然云端都配好了，为什么实训里还讲本地？** 两个原因：

1. **要能定位问题**：不知道 MCP/引擎/仓库各自负责什么，出故障时无法判断是哪一段坏了
2. **要能脱离平台**：本地路线让你在没有云端时也能复现、验证、继续开发

所以本实训凡是涉及环境的地方，都会给出 **🖥 本地 / 🌩 云端** 双栏对照（见 `STYLE.md`）。

## 2. 三件法宝：Agent、工具链与验证

### 2.1 Agent 协作协议（贯穿本实训）

本教程所有任务都遵循同一套节奏，叫 **G-V-C 循环**：

```
G（Goal 目标）      →  用一句话说清"这一任务做完，世界会有什么不同"
V（Verify 验证）    →  先写下"怎么证明做成了"（命令/断言/截图），再动手
C（Change 改动）    →  让 Agent 改代码，小步提交，每步都跑验证
```

每条任务里你都会看到可直接复制的三段：

- **🤖 Agent 提示词**：贴给 CodeBuddy 的完整指令（含上下文与约束）
- **✅ 验证命令**：一条命令证明成功（例如 `python tools/dev.py test`）
- **📦 产出物**：这一步应该新增/修改了哪些文件

> 反模式警告：不要让 Agent 一次性写一大段代码再一起跑。每 20～80 行就验证一次，
> 这是本实训所有任务能"一次做对"的唯一原因。

### 2.2 工具链（一次装好，整个实训复用）

| 工具 | 版本 | 用途 |
|---|---|---|
| Godot | 4.7.stable | 引擎、导入、导出 |
| Blender | 4.2（本地）/ 5.2（远程 pilot） | 程序化建模 |
| Python | 3.11+ | 工具脚本（`tools/`） |
| Node.js | 18+ | MCP 客户端与调试脚本 |
| `web-cb-blender-pilot` | 远程 MCP | 提交 bpy 脚本 → 产出 GLB + 预览 |
| `godot-mcp` | 本地 stdio MCP | 驱动本地 Godot（导入/运行/取日志） |
| Playwright | 1.40+ | 真实浏览器验收（可选但强烈建议） |

### 2.3 三层验证（本实训的质量地基）

```
第 1 层  引擎内断言    python tools/dev.py test     → 56 条世界/存档断言 + 12 条场景冒烟
第 2 层  Web 导出      python tools/dev.py export-web
第 3 层  真实浏览器    python project/tests/browser_smoke.py --base http://127.0.0.1:8184/index.html
```

> HTTP 200 不等于游戏能玩；点一下造出方块、撤销后它真的消失，才算数。

## 5. 视频与图文怎么配

本实训每章都附三个"媒体包"（见 `chapters/<章>/media.md`）：

1. **📹 录屏分镜脚本**：时间轴 / 画面内容 / 解说词 / 字幕要点，照着录即可，单章 8–15 分钟
2. **🖼 配图清单**：需要哪些截图、在哪一步截、命名规范；可用
   `python tools/course_capture.py --chapter 03` 自动批量产出（复用 Playwright 管线）
3. **📊 示意图**：架构与数据流的 SVG 源文件（可直接改字换色）

> 图不是装饰：每张图都要对应一个"可被验证的事实"（例如"这条命令跑完应该有 9 个 GLB"）。

## 7. 交付形态：Markdown 是设计稿，HTML 是成品

| 形态 | 位置 | 用途 |
|---|---|---|
| **Markdown** | `course/chapters/*.md`、`syllabus.md` | 写作与评审的设计稿（方便 diff、评审、AI 生成） |
| **HTML 站点** | `course/site/*.html` | **最终成品**：分章节、有导航与目录、图文内嵌、带视频位，可直接用于课堂与自学 |

生成与预览：

```powershell
python tools/course_build.py               # 重新生成整个站点
python tools/course_build.py --embed       # 图片/CSS 内嵌为 base64，单文件分发
python tools/course_build.py --serve 8200  # 生成后本地预览 http://127.0.0.1:8200/index.html
python tools/course_check.py               # 体检：配图引用、拍摄计划、字数统计
```

页面结构：顶部（卷/章/字数/生成时间）· 左侧章节导航 · 正文 · **本章图集（自动汇总截图）** ·
**视频位（放入 `course/media/video/<章号>/` 即自动内嵌，未录制时显示分镜提示卡）** · 上下章翻页。

**规则**：新增或修改任何一章，都必须重跑 `course_build.py` 并把 `course/site/` 一起提交——
站点与 Markdown 不允许不同步。

## 8. 怎么用这个仓库学

```powershell
# 1. 取代码
git clone https://github.com/oceancolor/Mist_Harbor.git
cd Mist_Harbor

# 2. 引擎路径（换机器只需改这里）
copy tools\tools.example.json .codebuddy\local\tools.json   # 然后编辑路径

# 3. 跑通基线
python tools/dev.py test

# 4. 打开游戏
python tools/dev.py run
```

教程正文在 `course/chapters/`，任务清单在 `course/syllabus.md`，直播脚本在 `course/live/`。
游戏工程本体在 `project/`，配套工具在 `tools/`。

- 本实训与仓库代码**同步演进**：章末标注"对应提交"，方便对照代码历史
